# Format Guide

How to format a finished case study for its destination. Load the section matching {{PUBLISH_PLATFORM}}, and check the context section that matches the intended use confirmed at the start of this stage.

The same case study is shown differently depending on the audience. Designers want process, leadership wants business impact, product managers want collaboration. Tailor which face you lead with.

## Portfolio Site (Markdown or HTML)

- Open with a hero block: title, one-line summary, your role, and the single strongest outcome.
- Use H2 for each anatomy section. Headlines should tell the story alone.
- Place curated images between sections, each with a one-line "why" caption.
- Always export a PDF backup. Firewalls block live portfolios, so a PDF must exist.

## Notion

- Use a callout block for the summary, role, and headline outcome.
- Toggle lists can hold supporting detail so the main read stays scannable.
- Embed curated images at full width; captions go in the line below as small text.
- Still produce a PDF backup.

## PDF or Slides

- One project, one core problem, 10-12 slides.
- One section per slide. Lead each with the section's headline sentence; large slide headlines.
- Keep body text short; let curated visuals carry weight.
- Cover slide: title, role, date. Closing slide: the reflection.

## Interview Presentation

- A tailored sales pitch, not a website read aloud. Script three acts per project: setup, decisions, outcome.
- Build a modular deck; present 2-3 projects and keep others in your back pocket.
- Credit collaborators and name which decisions you owned. Avoid too few visuals or too much polish.
- For spoken answers, use STAR for past work (Situation, Task, Action, Result) and METEOR for hypotheticals (Muse, Enquire, Theorize, Endeavor, Outcome, Recap).

## Asset Checklist

For every bracketed visual note in the case study, list the image needed, whether it exists, and where it goes. Hand this list to the user so missing visuals can be produced before publishing.
